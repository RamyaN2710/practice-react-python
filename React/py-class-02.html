tuple · live code

Tuples: data that should never change 📍

🔒 Immutable
No append/remove/assign. Only count() and index().
⚠️ (5) is just the int 5
The comma makes a tuple: (5,)
✅ Why use tuples?
Safe, a bit faster and smaller, and hashable: can be a dict key.

Aadhaar details: written once, read many times. A shopping list changes daily: that's a list.

  • Connect to Class 1: a, b = b, a swap is tuple packing + unpacking.
  • Ask: "Can a tuple contain a list?" Yes: t = (1, [2, 3]) and t[1].append(4) works, because the tuple still holds the same list object. Such a tuple is not hashable, though.
set · live code · UPI

Sets: kill duplicates, compare groups 🎯

🧹 Unique only
set(lst) removes duplicates (but loses order).
🔀 No order, no index
s[0] is a TypeError. Items must be hashable.
⚡ x in s is O(1)
Hash table: jumps straight to the item, no scanning.

{} is an empty dict. An empty set is set().

  • We print sorted(...) because a set has no guaranteed order: print a set of names twice in two runs and the order can differ.
  • Methods: add, remove (KeyError if missing), discard (silent), union, intersection, difference.

Dictionaries: instant lookup by key 🗂️

Live code · copying in practice

The [[0]*3]*3 trap & copy module 🪤

Why [[0]*3]*3 breaks
* 3 repeats the reference: one row object, three tags.
The fix
A comprehension builds a new row each time: [[0]*3 for _ in range(3)]
Shallow vs deep
Shallow (copy.copy, lst[:], .copy()): new outer, shared inner. Deep (copy.deepcopy): all new.
  • Ask why shallow["name"] is still "CSK": reassigning a key in team doesn't touch the copy's own dict. Only the shared inner list leaks.
  • [0] * 3 itself is fine, because ints are immutable. The trap only bites with mutable inner objects.

Compare & contrast · interview favourites

List vs tuple, list vs array, and unhashable keys ⚖️

📋 list vs 📍 tuple

list tuple
Mutable? Yes No
Syntax [1, 2] (1, 2)
Speed / memory More Less
Dict key? No Yes*
Use for Changing data Fixed records

* if everything inside it is hashable too

📋 list vs 🔢 array

list: holds any mix of types, stores references to objects.

array.array('i', [1, 2]): one type only, stores raw numbers compactly. Less memory.

NumPy array: one type, super-fast maths on the whole array (arr * 2). Used in data science.

🔑 Why can't a list be a dict key?

A dict stores each key in a slot chosen by hash(key). If the key could change (like a list), its hash would change and the dict could never find it again. So only immutable (hashable) objects can be keys.

  • For each column, ask the class to answer before revealing. These three come up again and again in fresher interviews.
  • Analogy for hashing: a library shelf number calculated from the book title. If the title could change after shelving, nobody could find the book.

🎯 Interview corner · 75–90 min

Questions you will be asked (1/2)

Ask, let students answer out loud, then click to reveal the model answer.

What is the difference between a list and a tuple?

List is mutable ([ ]), tuple is immutable (( )). Tuples are slightly faster, use less memory and are hashable, so they can be dict keys. Use a tuple for fixed records, a list for data that changes.

append() vs extend()?

append(x) adds x as one element (a list becomes a nested list). extend(seq) adds each element of seq. [1].append([2,3]) → [1, [2, 3]]; extend → [1, 2, 3].

sort() vs sorted()?

lst.sort() sorts the list in place and returns None; only for lists. sorted(x) returns a new list and works on any iterable (tuple, set, dict, string). Both accept key= and reverse=.

Why can't a list be a dictionary key?

Dict keys must be hashable: their hash must never change. A list is mutable, so its hash could change and the dict would lose it. Python raises TypeError: unhashable type: 'list'. Use a tuple instead.

What is the difference between shallow and deep copy?

A shallow copy (copy.copy, lst[:]) creates a new outer object but shares nested objects. A deep copy (copy.deepcopy) recursively copies everything, so changes to nested items never leak.

Pick students at random. Coach the structure: definition → example → one extra detail (e.g. "and tuples can be dict keys"). The extra detail is what gets them selected.
🎯 Interview corner

Questions you will be asked (2/2)

remove() vs pop() vs del?

remove(x) deletes the first matching value (ValueError if absent). pop(i) deletes by index and returns the item (default last). del lst[i] is a statement; it can also delete slices or the whole variable.

What is the time complexity of x in list vs x in set?

List: O(n), it checks items one by one. Set (and dict keys): O(1) on average, because it uses a hash table to jump straight to the slot.

When does the else of a for loop run?

When the loop finishes normally, i.e. without hitting break. Common use: searching. If found → break; else → "not found". Same for while-else.

What is a list comprehension? Is it faster?

A one-line way to build a list: [expr for x in seq if cond]. Usually faster than a for loop with append (less overhead) and more readable. Dict and set comprehensions exist too; there is no tuple comprehension.

What is the difference between a list and an array?

A list can hold mixed types and stores references. array.array and NumPy arrays hold one type, stored compactly: less memory, and NumPy supports fast element-wise maths. Use lists for general code, NumPy for heavy numeric work.

If time is short, do the first four: they are the most frequently asked.

Watch out

Common mistakes 🚧

Saving the result of sort()

marks = marks.sort()

Now marks is None. Use marks.sort() alone, or sorted(marks).

Changing a list while looping

for x in lst: lst.remove(x)

Skips items. Loop over lst[:] or build a new list with a comprehension.

{} as an empty set

seen = {}

That's a dict. seen.add(x) → AttributeError. Use set().

The "or" trap

if city == "Chennai" or "Madurai":

Always True (a non-empty string is truthy). Write if city in ("Chennai", "Madurai"):

"Copying" with =

backup = cart

Same list, two names. Use cart.copy(), or copy.deepcopy for nested data.

Using d[key] for a maybe-missing key

count[w] += 1

KeyError on the first word. Use count.get(w, 0) + 1 or Counter.

Paste the "or" trap into a playground with city = "Delhi": it still prints. It's one of the most common bugs in fresher code tests.
