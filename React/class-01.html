Definition

What is React?

React is a JavaScript library for building user interfaces, the part of an app you see and click.

  • Created by Meta (Facebook), released as open source in 2013
  • Builds the UI from small reusable pieces called components
  • You describe what the screen should look like, and React handles how to update it
  • Used by millions of developers and one of the most in-demand frontend skills
🧱

React is like LEGO

A LEGO castle is built from small bricks. You build each brick once and reuse it everywhere: windows, doors, towers.

A React app works the same way: Navbar + ProductCard + Footer snap together to make a full website.

Stress the word library: React focuses only on the UI (the view). Routing and data fetching come from other tools, which we will learn later.
Why React · 10–20 min

Why do we need React?

Plain HTML and JavaScript work, but big apps get messy fast. Tap each card to see React's fix.

📋

Copy-paste code

Same navbar HTML pasted on 20 pages

✅ Components

Write <Navbar /> once and reuse it everywhere. Fix it once and every page is fixed.

🔧

Manual DOM updates

Find each element and change it by hand

✅ Automatic UI

Change the data and React updates the screen for you.

🔀

Out-of-sync screens

Cart says 3 items, badge says 2 😬

✅ Single source of truth

The data (state) lives in one place and every part of the UI reads from it.

🍝

Spaghetti code

One 3,000-line JS file nobody understands

✅ Organized files

Each component lives in its own small file that is easy to read and test.

Restaurant menu board: if the price of a dosa changes, would you repaint the whole board? No. You swap just that price card. React does the same thing for web pages.

Let students tap the cards (or tap them yourself). The menu board analogy sets up the Virtual DOM idea that comes later.
Big idea

Declarative UI: say what, not how

🚕

Imperative (plain JavaScript)

Like guiding an auto driver at every turn:

"Go straight… turn left… stop at the signal… turn right… stop here."

You write every step: find the element, change its text, add a class, remove a class…

📱

Declarative (React)

Like booking a cab in an app:

"Take me to the Railway Station."

You describe the result ("when count is 5, show 5"), and React works out the steps.

Students don't need to understand useState yet (that is Class 7). Point out that in React we never write textContent = .... We only describe what to show.
Comparison

HTML, CSS, JavaScript… and React?

🧱

HTML

The structure: walls, doors and rooms of a house.

🎨

CSS

The style: paint, curtains and decoration.

⚡

JavaScript

The behaviour: electricity, switches and fans.

🏗️

React

A smart builder that uses all three to make ready-made rooms you can reuse.

Plain HTML + JS React
Reuse UI Copy and paste HTML Reusable components
Updating the screen Manual DOM changes Automatic when data changes
Code organisation Big files, mixed logic Small, focused component files
Best for Simple static pages Interactive apps (dashboards, shops, social media)
Important: React does not replace HTML, CSS or JS. It is built on top of them. We still write HTML-like code (JSX), CSS and JavaScript.

Concept

JSX: HTML-like code inside JavaScript

React components return JSX. It looks like HTML, but it lives inside JavaScript.

  • A component is just a JavaScript function
  • It returns what should appear on the screen
  • Component names start with a Capital letter
  • We'll master JSX in Class 3 🚀

Guess: what does the browser actually run? 👉 React.createElement("h1", null, "Welcome to React"). JSX is converted into plain JavaScript behind the scenes.

Click the blurred text to reveal it. This is the code example from the syllabus. Read it line by line: function → return → JSX → export.
Concept · high level

The Virtual DOM: React's smart shortcut

React keeps a lightweight copy of the page in memory, compares old and new, and updates only what changed.

🧠 Virtual DOM (in memory)

<div class="product">
<h3>Headphones</h3>
<p>₹1,499</p>
<span>In stock</span>
⇄compare
(diffing)

🌐 Real DOM (browser screen)

<div class="product">
<h3>Headphones</h3>
<p>₹1,499</p>
<span>In stock</span>
Click a button and watch which line changes.

Spot the difference: like the newspaper puzzle, React compares two pictures (before and after) and fixes only the differences, instead of redrawing the whole page.

Keep it high-level. Yellow = React found a difference in memory; green = React patched only that line on the real screen. The other lines are untouched, and that is why React is fast.

Class exercise · 3 min

🕵️ Component detective

Open Amazon, Flipkart, YouTube or any familiar website. Find five components.

1️⃣

Look for repeats

Anything that appears again and again (product tiles, video thumbnails) is a component.

2️⃣

Give it a name

Use PascalCase, e.g. VideoCard, SearchBar, RatingStars.

3️⃣

Share it

Which component appears the most times on the page?

Example answers on YouTube: Header, SearchBar, VideoCard, Sidebar, SubscribeButton, CommentBox.

Give 3 minutes. Pick 2–3 students to share their answers. Praise good names and gently correct names like "box1".
