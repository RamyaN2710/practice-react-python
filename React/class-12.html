Concept · 10–15 min

What is a side effect?

Rendering = calculating JSX from props and state. A side effect is any extra work that touches something outside that calculation.

🏷️Change the tab title

document.title

⏱️Start a timer

setInterval, setTimeout

🌐Fetch data

ask a server (Class 13–14)

👂Listen to the browser

window resize, key press

🌃

Automatic street lights

The street (your component) is just there. But it is synchronized with something outside it: the sun. When it gets dark, the lights switch on automatically.

An effect keeps your component in sync with something outside React, like a timer or a browser event.

  • Read the simple explanation from the syllabus: "An effect can synchronize a component with something outside React, such as a timer or a browser event."
  • Second analogy if needed: cooking is the render. Switching off the gas after cooking is a side effect. It is not the dish, but it must happen after cooking.
  • Ask: "Can you think of another app that changes something outside the page?" (music player tab, notifications).
Syllabus code · 15–20 min

Our first useEffect

1️⃣Import it from "react", just like useState.
2️⃣First argument: a function. "What should I do?" Here: set the tab title.
3️⃣Second argument: the dependency array [count]. "When should I do it again?" Only when count changes.
⏰Timing: React first paints the screen, then runs the effect. Effects run after render.
  • Read the code top to bottom. Pause on the backticks: this is a template string, so ${count} puts the number inside.
  • Say the sentence slowly: "After every render where count changed, set the title."
  • Common mistake: putting document.title = ... directly in the component body. It works, but it runs on every render and breaks the "render should be pure" rule.

Dependency arrays · 25–30 min

The dependency array decides when

Guess first, then click the blurred answer.

You write It runs… Real-life version
useEffect(fn)
no array		 After every render 🔁 A shop watchman who checks the lock every time anyone walks past.
useEffect(fn, [])
empty array		 Only once, after the first render (mount) 1️⃣ Saying "Welcome!" once when a guest enters the house.
useEffect(fn, [count])
with values		 After the first render, then only when count changes 🎯 A cricket scoreboard operator who updates the board only when the score changes.

Rule of thumb: put every value from props or state that the effect uses inside the array. The effect uses count? Then write [count].

  • For each row, ask the class to vote before you click the spoiler.
  • Students often think "no array" and "empty array" mean the same thing. They are opposites: every time vs only once.
  • Transition: "Let's see all three running side by side in a simulator."

Lifecycle · 35–40 min

A component's life: born, changes, leaves

🐣

Mount

The component appears on screen for the first time.

useEffect(fn, []) runs here.

🔄

Update

State or props change, so it re-renders.

useEffect(fn, [count]) runs again if count changed.

👋

Unmount

The component is removed from the screen.

The cleanup function runs here.

A hotel stay: check in (mount) and get your room key. During your stay you order chai many times (updates). When you check out (unmount) you return the key (cleanup), so the next guest is not locked out.

  • Older React used class methods like componentDidMount. Mention it only if someone has seen it on YouTube. With hooks we think in "sync with something", not in lifecycle methods, but the three stages help beginners.
  • Ask: "When you switch from the Home tab to the Profile tab in an app, which components unmount?"
Cleanup · 40–43 min

Cleanup: switch off the tap before you leave 🚰

You open the tap to fill a bucket (start the timer). When you leave the bathroom, you switch off the tap (clear the timer). If you forget, water keeps running and is wasted, even though nobody is there.

How: return a function from your effect. That returned function is the cleanup.
What to clean: setInterval → clearInterval, addEventListener → removeEventListener.
  • Point at line 5 (start) and lines 9–11 (stop). Every "start" needs a matching "stop".
  • Not every effect needs cleanup. Setting document.title does not leave anything running, so no cleanup is needed.
  • Next slide shows what happens if we forget.

Big idea · 45–48 min

Effect or event handler? 🤔

🔔

Event handler

Runs because the user did something: click, type, submit.

Like a doorbell: it rings only when someone presses it.

onClick={() => setCount(count + 1)}

🌃

Effect

Runs because the component rendered and something needs to stay in sync.

Like street lights: they switch on because it got dark, not because someone pressed a button.

useEffect(() => {...}, [count])

Situation Use
"Place order" button sends the order 🔔 Event handler (user clicked)
Tab title shows the cart count 🌃 Effect (keep title in sync with state)
Clock on the screen ticks every second 🌃 Effect (timer starts when it appears)
Show "Copied!" after clicking Copy UPI ID 🔔 Event handler
  • This is the To Practice question, so spend time here.
  • Easy test for students: "Is there a specific user action that causes it? Then it's an event handler. Should it happen just because the component is on screen? Then it's an effect."
  • Common mistake: using an effect to react to a button click (setting a flag, then an effect watching the flag). Just do the work inside the click handler.

Extra practice · fast finishers

🕒 Build a live digital clock

You need setInterval to tick every second, plus cleanup to stop it.

Stuck? useEffect(() => { const id = setInterval(() => setTime(new Date()), 1000); return () => clearInterval(id); }, []);
  • For students who finish the tab title exercise early.
  • Reveal the spoiler only after 3–4 minutes.
  • Bonus idea: show "Good morning / Good evening" based on time.getHours().
Watch out

⚠️ Common useEffect mistakes

♾️ Infinite loop

Setting state in an effect with no array: set state → re-render → effect → set state → …

useEffect(() => setCount(count + 1)); ❌

🙈 Missing dependency

The effect uses count but the array is [], so the title gets stuck at "Count: 0".

Fix: [count] ✅

🚰 Forgetting cleanup

Timers and listeners keep running after the component is gone. Return a cleanup function.

🔔 Effect for a click

If it happens because the user clicked, put it in the event handler, not in an effect.

Never try the infinite loop in the playground during class: the preview can freeze. Just explain it on the board.

  • Draw the infinite loop as a circle on the board: render → effect → setState → render…
  • In a real project, the ESLint rule react-hooks/exhaustive-deps warns about missing dependencies. Vite templates include it.
  • Also mention: in development, React StrictMode runs effects twice on mount to help you find missing cleanups. Don't panic if you see two logs.
