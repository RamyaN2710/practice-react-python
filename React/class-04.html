Concept · 05–15 min

A component is just a function

A function component is a JavaScript function that returns JSX.

  • Write it once as a function
  • Use it like an HTML tag: <Header />
  • Use it as many times as you want
🖋️

A rubber stamp

The college office has a "VERIFIED" rubber stamp. They made it once, and they stamp it on hundreds of forms.

The function is the stamp. Each <Header /> on the page is one stamp mark.

Point out: "You already wrote a component! App is a component." Every component works exactly the same way.
Rule

Component names start with a Capital letter 🔠

Name OK? Why
Header ✅ Capital letter, clear name
ProfileCard ✅ PascalCase: every word starts with a capital
header ❌ React thinks it is the HTML <header> tag
profile-card ❌ Dashes are not allowed in function names
Box1 😕 Works, but nobody knows what it is
🪪

Names vs common words

We write Priya, Chennai and Flipkart with a capital letter because they are names.

Same in React: <footer> is a common HTML tag, but <Footer /> is your component with its own name.

Common mistake: function header() then <header />. No error appears, but React draws an empty HTML header tag instead of the component. Very confusing for beginners, so stress it.
Code example

Three components working together

1️⃣Define small components: Header and Footer.
2️⃣Use them inside App like tags: <Header />, <Footer />.
3️⃣Notice <footer> (HTML tag, lowercase) inside Footer (component, capital). Both exist!

Concept · 15–25 min

Parent and child components 👨‍👩‍👧

When a component uses another component, it becomes the parent. The one inside is the child.

🏠<App />parent of everything
↓
<Header />child of App
<ProfileCard />child of App
<Footer />child of App
↓
<Logo />child of Header
<Avatar />child of ProfileCard
🏡

A joint family

Grandfather (App) → father and uncle (Header, ProfileCard) → children (Logo, Avatar).

Everyone is someone's child, and some are also parents. The whole family tree is your app.

Ask: "Is Header a parent or a child?" (Both: child of App, parent of Logo.) This tree is how React DevTools shows your app, which we will use in Class 18.
Composition

Composition: build big things from small things 🍽️

🍽️

A South Indian thali

A thali is not one big dish. It is rice + sambar + rasam + poriyal + curd + payasam, each in its own katori.

Want a new meal? Swap one katori. Your page works the same way: combine small components to make a full page.

How to break a page into parts: draw boxes around anything that (1) repeats, (2) has one clear job, or (3) is big enough to deserve a name.

Highlight that ProfileCard is used twice and that ProfileCard itself contains another component (Avatar). Components inside components inside components: that is composition.

Import & export · 25–35 min

One component per file: export it, then import it 📤📥

📚

Borrowing a book from the library

export = the library puts the book on the shelf so others can borrow it.

import = you borrow it and use it in your room.

If the book was never put on the shelf (no export), nobody can borrow it.

  • Click through the tabs in order. In VS Code, create src/components/ and make these files live.
  • The path ./components/Header starts with ./ which means "from this folder". The .jsx extension is optional with Vite.
Import & export

Default export vs named export

⭐

Default export

The main thing a file shares. Only one per file.

🏷️

Named export

A file can share many things by name.

A restaurant menu: the default export is the "Chef's special" (one per restaurant, and you can just say "give me the special"). Named exports are the other dishes: you must ask for them by their exact name, like "one masala dosa".

Beginner tip: use export default for one component per file. Mixing up { } is the #1 import error: "does not provide an export named…".

Don't spend too long here. The key rule: default = no braces, named = braces and exact name.

Class exercise · 35–52 min

🧪 Split the page into Header, ProfileCard and Footer

Everything is in one big App right now. Move each part into its own component.

  • Give 8–10 minutes. The page should look exactly the same after the change. That is the point: same UI, better organized code.
  • Common mistakes: lowercase component names, forgetting return, defining a component inside App (works, but bad practice), and forgetting the / in <Header />.
  • Students with VS Code can do it with real files in src/components/ and import them.
Common mistakes

⚠️ Component mistakes to avoid

❌ Mistake What happens ✅ Fix
function footer() + <footer /> Your component is ignored, an empty HTML tag is drawn Capital letter: Footer
Forgot return in the component Nothing shows on the screen return <h1>...</h1>;
Forgot export default "does not provide an export named default" Add export default Header;
import Footer for a named export Import error import { Footer }, or make it default
Wrong path: "./Header" "Failed to resolve import" "./components/Header"
Calling it like a function: {Header()} Works sometimes, breaks later Use it as a tag: <Header />
Read each mistake and ask "What will happen?" before revealing the middle column.
