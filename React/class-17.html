Quick recap · 00–05 min

Last class: state, props and data flow

Tap a card only after someone in the class has answered it out loud.

⬇️

One-way data flow

Data flows down from parent to child through props, like water flowing down a waterfall.

🏠

Who owns state?

The component that creates the state is the only one that changes it, using its setter function.

⬆️

Lifting state up

When two children need the same data, move the state to their closest common parent.

🎁

Props vs state

Props: read-only inputs from the parent. State: the component's own memory that can change.

Today's link: so far our state was mostly a number or a string. Real apps keep lists (tasks, cart items, messages) and objects (a user profile) in state. Updating those needs one special rule.

Concept · 15–30 min

The golden rule: immutability

Immutable means "not changed". In React, we never change the array or object that is already in state.

  • Make a new copy of the array or object
  • Change the copy (add, remove or edit)
  • Give the copy to the setter: setTasks(newCopy)
  • React sees a new value and re-renders the screen
📄

The exam answer sheet

You never scribble on the original answer sheet that the examiner has already checked. You take a photocopy, make your corrections on the copy, and submit the copy.

Now the examiner can clearly see: "This is a new sheet, let me check it again."

  • Write the word "immutable" on the board. "Mutate" = change. "Im-mutable" = not changed.
  • Ask: "If you secretly change the original sheet, would the examiner notice? No! That is exactly our cart bug."
Concept · how React decides

React asks one quick question: "Is it the same box?"

React does not open the box and compare every item. That would be slow for a list of 10,000 items. It only checks the address of the box. This is called a reference check.

💂

The society watchman

The watchman checks the tracking number on each parcel. He doesn't open it. Same tracking number? "Already logged, ignore it."

push() puts a new item inside the same parcel. Same tracking number, so the watchman ignores it. A new parcel gets a new number, and he logs it.

  • Key sentence: "React compares the box, not what is inside the box."
  • Ask: "So how do we make React notice a change?" Answer: give it a brand new box (a new array).

      Concept · the copy machine

      The spread operator ... makes copies

      Three dots mean "take everything out of this box and put it here".

      🍱

      A new tiffin box

      Amma packs your lunch. You want to add a samosa, but the old box is full and already labelled. So you take a new tiffin box, move everything from the old one into it (that's the ...), and add the samosa on top.

      • Show both tabs. Point at copy === snacks being false: same items, but a different box.
      • For objects: keys written after the spread win. So fees: 3999 replaces the old fees.
      • Common question: "Is it slow to copy?" No, for normal app data it is very fast.
      Adding items · 30–40 min

      Adding a task the React way

      Line 1: tasks starts as an empty array [].
      Line 4: we pass a function to the setter. React gives us previousTasks, the latest list.
      Line 5: ...previousTasks copies all old tasks into a new array.
      Line 7: Date.now() gives a unique number (milliseconds), perfect for a key.

      Why previousTasks? Like asking the shopkeeper "What's the latest bill?" before adding an item. You always add to the newest version.

      • This is the syllabus example. Read it line by line with the class.
      • setTasks([...tasks, newTask]) also works. The updater form prev => [...] is safer when you update many times quickly (we saw this with counters).
      • Each task is an object with id and title, so it's an array of objects.

      Deleting items

      Delete with filter(): keep what you want

      • filter() returns a new array. The old one is untouched.
      • Return true to keep an item, false to drop it.
      • Read it as: "keep the tasks whose id is not this id".
      ☕

      The chai strainer

      Pour chai through a strainer: the tea goes into a new cup, the tea leaves stay behind. You don't pick the leaves out of the pan one by one.

      filter pours your list through a test. Items that pass go into a new array.

      • Stress !== (not equal). A common mistake is ===, which deletes everything except the clicked task.
      • Also remind them: onClick={() => deleteTask(task.id)} needs the arrow function because we pass an argument (Class 6).
      • Avoid splice(): it changes the original array.
      Updating objects

      Change one key, keep the rest

      🪪

      Changing the address on your college ID

      The office gives you a new form. You copy your name, roll number and course exactly as before, and write only the new address. Forget to copy the name? Your new ID card has no name!

      Nested objects: copy each level you change: { ...user, address: { ...user.address, pin: "560001" } }

      • Walk through all three versions. Ask the class to predict what happens in each one before you explain.
      • The third mistake is very common: students think setUser "merges" like old class components. It does not; it replaces.
      • Nested objects: mention it briefly. Beginners should keep state flat when possible.
      Updating one item in an array

      Update one item with map()

      An array of objects (like cricket players) where only one object should change.

      Rohit32 runs
      ➡ copied as is
      Virat45 runs
      ➡ new object: 49
      Gill12 runs
      ➡ copied as is
      🏏

      The scorer's new sheet

      The scorer writes a fresh score sheet after every ball. For each batter he asks: "Is this the one who hit the four?"

      Yes: write the new score. No: copy the old line exactly. That's map() with a ternary.

      • Read the ternary aloud: "If this is the player, make a new copy with more runs, otherwise keep the old player."
      • map() always returns a new array with the same length. filter() can make it shorter.
      • To Practice uses this exact pattern to toggle a task's completed status.
      Cheat sheet · screenshot this!

      The 4 patterns you will use every day

      I want to… ✅ Do this (new copy) ❌ Not this (mutates)
      ➕ Add an item setArr([...arr, item]) arr.push(item)
      🗑️ Remove an item setArr(arr.filter(x => x.id !== id)) arr.splice(i, 1)
      ✏️ Update one item setArr(arr.map(x => x.id === id ? { ...x, done: true } : x)) arr[i].done = true
      🧾 Update an object setObj({ ...obj, key: value }) obj.key = value
      🔤 Sort a copy setArr([...arr].sort()) arr.sort()

      Memory trick: Spread to add, Filter to remove, Map to update. Like paying with UPI: you never change the old receipt, every payment makes a fresh one. 💸

      • Ask students to take a photo of this slide. It is the most useful slide today.
      • Other mutating methods to avoid on state: pop, shift, unshift, reverse.
      • [...arr].sort(): copy first, then sort the copy.

      Watch out

      ⚠️ Common mistakes

      Using push, splice, sort

      They change the original array. Same box, so the screen may not update.

      ✅ Use spread, filter, map, or copy first: [...arr].sort()

      Forgetting ...obj

      setUser({ city: "Delhi" }) throws away name and plan.

      ✅ setUser({ ...user, city: "Delhi" })

      === instead of !== in filter

      Clicking ❌ deletes every other task. 😱

      ✅ tasks.filter((t) => t.id !== id)

      Forgetting the "else" in map

      map(t => t.id === id && {...t, done: true}) turns other tasks into false.

      ✅ Always return the old item: ? {...t, done: true} : t

      • Reveal one card at a time and ask: "Who made this mistake in the exercise?" Make it okay to admit it.
      • Bonus: using the array index as a key breaks when you delete from the middle. Use id.
