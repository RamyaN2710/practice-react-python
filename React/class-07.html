How does a scoreboard remember the score?

Every ball, the score changes. The board must remember the old score and show the new one.

  • 🛒 Flipkart cart badge: remembers how many items you added
  • ❤️ Instagram: remembers if you liked a post
  • 🍔 Swiggy: remembers the quantity of each dish
  • 🌙 Any app: remembers dark mode on or off

Experiment · Try it!

Attempt 1: a normal let variable 🤔

Click the button 3 times. Then look at the console under the preview.

  • Click 3 times. Console shows 1, 2, 3. Screen still shows 0.
  • Ask: "Is the variable changing?" Yes, console proves it. "Is the screen changing?" No.
  • Why? React has no idea the variable changed. React only redraws a component when it is told to. A normal variable cannot tell React anything.
  • Bonus point: even if React re-ran App(), the line let runs = 0 would reset it to 0. A normal variable has no memory between renders.
Why it fails

Two problems with a normal variable

🙈

1. React is not told

Changing runs = runs + 1 only changes a value in memory. React does not watch normal variables, so it never redraws the screen.

🧽

2. No memory between renders

Each time React runs App(), the line let runs = 0 runs again. The value is wiped clean, like a whiteboard erased after every class.

✅

We need something that does both

It must remember the value between renders, and tell React to redraw when the value changes. React gives us exactly that: useState.

Keep this short (2 minutes). The whiteboard image works well: normal variable = whiteboard wiped after every render; state = a notebook React keeps safe for you.
Concept · 12–27 min

What is state?

State is data that a component remembers, and that can change over time. When state changes, React updates the screen.

  • State is the component's memory
  • It survives between renders (it is not wiped)
  • Changing it makes React re-render the component
  • Examples: a count, a typed name, "is the menu open?", a list of cart items
🏟️

State is the cricket scoreboard

The board remembers the score between balls. When a four is hit, the scorer updates the board, and everyone in the stadium instantly sees the new score.

Score = state. The scorer's update = the setter function. The crowd seeing it = re-render.

  • Repeat the one-line definition and ask the class to say it back.
  • Ask: "On a Swiggy cart page, what would be state?" (quantity, selected address, coupon applied, total).
Concept · useState

One line, three parts

const [count, setCount] = useState(0);
👀

count

The current value. Read it in your JSX: {count}. Like the number on the scoreboard.

✍️

setCount

The setter function. The only correct way to change the value. Like the official scorer's pen.

🏁

0

The initial value, used only on the very first render. Like 0 runs at the start of a match.

Naming rule: [thing, setThing]. For example [likes, setLikes], [name, setName], [isOpen, setIsOpen]. And don't forget import { useState } from "react"; at the top.

  • Point at each coloured part as you reveal its card.
  • Hooks rule (keep simple): call useState at the top of your component, not inside an if or a loop.
JavaScript refresher

What are those [ ] brackets? 🍱

useState returns an array with two items. Array destructuring unpacks both into named variables in one line.

🍱

A two-compartment tiffin box

Mom hands you a tiffin with two compartments: rice in the first, sabzi in the second. You open it and take both out at once.

useState hands you a box with the value first and the setter second. The order matters, the names are your choice.

Click through the three tabs. Students who are new to JavaScript often think [count, setCount] is "special React syntax". It is plain JavaScript array destructuring. Ask: "What if I wrote [setCount, count]?" (the names would be swapped and confusing).
Concept · initial values

State can hold any kind of value

The value you pass to useState() is where the component starts.

Code Type Real-life use
useState(0) Number 🛒 Items in cart, likes, cricket runs
useState("") String ⌨️ Text typed in a search box
useState(false) Boolean 🌙 Is dark mode on? Is the menu open?
useState([]) Array 📋 To-do list, list of students
useState({ name: "Priya", age: 20 }) Object 👤 A user profile, a form

A new notebook: the initial value is what you write on the first page. After that, you only change it with the setter. React ignores the initial value on later renders, just like you don't rewrite page 1 every day.

Today we mostly use numbers. Strings come back in Class 10 (forms), booleans in Class 8 (conditional rendering), arrays in Class 9 and Class 17.
Concept · setter function

Change state only through the setter

❌

Changing it directly

Like scribbling on the scoreboard with chalk. The official score is not updated and nobody is informed.

✅

Using the setter

Like asking the official scorer. The board updates and the whole stadium sees it.

Surprise: the setter does not change count immediately in the current line. setCount(5); console.log(count); still logs the old value. The new value arrives in the next render.

Pro tip (for later): when the new value depends on the old one, you can also write setCount(c => c + 1). Both are fine for today.

  • The "surprise" callout causes a lot of confusion. Explain: calling the setter is like placing an order. The food (new value) arrives with the next render, not on the same line.
  • Only mention the updater function briefly. We will use it more in Class 17.

Watch out

🐞 Common state mistakes

1. Calling the setter in onClick

onClick={setCount(count + 1)}

Runs during render → "Too many re-renders". ✅ onClick={() => setCount(count + 1)}

2. Changing state directly

count++ or count = 5

React is not told, the screen doesn't change. ✅ Always use setCount(...)

3. Forgetting the import

useState is not defined

✅ Add import { useState } from "react"; at the top of the file.

4. Expecting the new value immediately

setCount(5); console.log(count);

Logs the old value. The new value appears in the next render.

Ask students which mistake they made during the exercise. Most classes hit mistake 1 at least once.

Initial value

The starting value: 0, "", false, []… used on the first render only.

Setter function

The only correct way to change state. Never write count++.

Re-render

React calls your component again → new JSX → only the changed parts update.

Normal variables

Reset on every render and don't tell React. Fine for calculated values like bill.
