Tool 1 · 05–15 min

Node.js 🟩

Node.js lets JavaScript run outside the browser, directly on your computer.

  • Before Node, JavaScript could only run inside a browser like Chrome
  • With Node, JavaScript can run tools on your laptop: create projects, start servers, build apps
  • Vite and npm are written in JavaScript, so they need Node to run
  • Always install the LTS version (Long Term Support = stable)
👩‍🍳

A chef who leaves the restaurant

JavaScript was a chef who could only cook in one kitchen: the browser.

Node.js gives the chef a portable stove, so now JavaScript can cook anywhere, even on your laptop.

  • Open a terminal and run node -v live. Any version 20 or above is fine. Your numbers may differ from the slide.
  • If students see "not recognized", they need to install Node or restart the terminal (see the troubleshooting slide).
Tool 2

npm: the grocery delivery app for code 🛵

npm (Node Package Manager) downloads code that other developers wrote and shared, called packages.

🛵

Like ordering on a grocery app

You don't grow your own rice and onions. You order them and they arrive at your door.

You don't write React from scratch. You type npm install and React arrives in your project.

📝package.json = your shopping list. It lists the packages your project needs.
🥫node_modules = your pantry. The downloaded packages are stored here.
📦npm install = place the order. It reads the list and fills the pantry.
▶️npm run dev = start cooking. It runs a script written in package.json.
Mention that npm has more than 2 million packages. Ask: "If the pantry is lost, can we get it back?" Yes, just run npm install again, because the shopping list (package.json) is still there. That is why we never share node_modules.

Node.js

  • Go to nodejs.org and download the LTS version
  • Run the installer and click Next with the default options

📘

VS Code

  • Go to code.visualstudio.com and install it
  • Open the built-in terminal with Ctrl + `

  • Walk around while students install. Pair a student who has it working with one who does not.
  • The PowerShell "running scripts is disabled" error is common on Windows. Switching the VS Code terminal to Command Prompt is the quickest fix for class.
Tool 3 · 15–25 min

Vite ⚡ creates the project in 4 commands

Vite (French for "fast", say "veet") is a build tool. It creates a ready-made React project and runs it instantly.

Command In simple words
npm create vite@latest "Vite, please give me a new React kitchen called my-app."
cd my-app "Walk into that kitchen." (cd = change directory)
npm install "Fill the pantry." Downloads everything in package.json.
npm run dev "Start cooking." Opens the app at localhost:5173.

If Vite asks extra questions (like "Select a variant"), choose JavaScript and accept the defaults. You only run step 1 once per project. Next time, just cd into the folder and run npm run dev.

  • Type these live in VS Code's terminal. The -- in step 1 passes the --template react option through to Vite.
  • Common mistake: students run npm install before cd my-app. It fails because there is no package.json in the outer folder.

Development server

The dev server: your rehearsal stage 🎭

🎭

Rehearsal before the college fest

Before the real show, you rehearse on stage. Only your team watches, and you can fix mistakes instantly.

npm run dev is the rehearsal stage. The app runs only on your laptop (localhost), and every change shows up immediately.

🏠localhost:5173: "localhost" means this computer, and 5173 is the door number (port) Vite uses.
🔥Hot reload (HMR): save a file and the browser updates in under a second, without a full refresh.
⏹️Stop the server with Ctrl + C in the terminal. Keep the terminal open while you work!

Later, npm run build makes the final show version (in a dist folder) that you can put on the internet. We'll do that at the end of the course.

Demonstrate hot reload live: put VS Code and the browser side by side, change the heading, press Ctrl+S. The class should see the page update without a reload. Then stop the server with Ctrl+C and refresh the browser to show it no longer works.

How it connects

How does the app reach the screen? 🔗

Four files pass the baton, like a relay race.

🌐index.htmlhas an empty <div id="root">
→
🔌main.jsxfinds #root, renders <App />
→
⚛️App.jsxreturns the JSX for the page
→
🖥️Screenyou see the page
index.html 
<!doctype html><html lang="en">  <head>    <title>Vite + React</title>  </head>  <body>    <div id="root"></div>   <!-- empty box, React fills it -->    <script type="module" src="/src/main.jsx"></script>  </body></html>
  • Reveal the flow first, then click each tab in order: index.html → main.jsx → App.jsx.
  • createRoot: "React, take control of this empty div." render: "Draw App inside it."
  • StrictMode is a helper that warns about problems during development. It does not show anything on screen.
  • Ask: "If I delete <div id="root"> from index.html, what happens?" (Blank page, because React has nowhere to draw.)
Key files

main.jsx vs App.jsx

🔌

main.jsx: the main switch

  • The entry point: the first JavaScript file that runs
  • Connects React to the #root div in index.html
  • Renders <App /> once
  • You rarely change it
⚛️

App.jsx: the main room

  • The root component: the parent of all others
  • Returns the JSX you see on the page
  • Ends with export default App so main.jsx can import it
  • You change it all the time

A TV: main.jsx is the power button. You press it once to turn the TV on. App.jsx is the channel you watch. You change channels (the content) all day, but you don't keep rewiring the power button.

This slide answers the To Practice question "Identify the purpose of App.jsx and main.jsx". Ask 2 students to explain it back in their own words before moving on.

🩺 Troubleshooting: when it doesn't work

You see… Why it happens Fix
'npm' is not recognized Node.js is not installed, or the terminal was open during installation Install Node LTS, then close and reopen the terminal (or restart VS Code)
Could not read package.json / ENOENT You forgot cd my-app, so you are in the wrong folder Run cd my-app first. Check the folder name in the terminal
Port 5173 is in use, trying another one... Another dev server is already running Use the new address it prints (e.g. 5174), or stop the old one with Ctrl+C
vite is not recognized You skipped npm install Run npm install, then npm run dev
Page does not change after editing File not saved, or you edited the wrong file Press Ctrl+S. Edit src/App.jsx
"This site can't be reached" The terminal running the server was closed Run npm run dev again and keep it open
Read each error aloud and ask the class to guess the fix before revealing it. Tell students: "Errors are not failures. They are clues. Read the message slowly."
