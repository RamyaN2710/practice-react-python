Functions: write once, call anywhere

Ask: "How many times does Swiggy calculate a bill each day?" Millions. It's the same code, called again and again: a function.

Get one or two guesses, then reveal: one function, millions of calls. DRY = Don't Repeat Yourself.
Function basics

def, return, parameters vs arguments

A function is the tea stall recipe. "Cups" and "price" are blanks in the recipe (parameters). When you order "3 cups", 3 is the real value you hand over (argument). The bill you get back is the return value.

🔁 return vs print
return hands a value back to the caller and ends the function. print only shows it on screen. No return → the function returns None.
📝 Docstring & type hints
The """...""" line is read by help() and IDEs. Hints like name: str are not enforced at runtime; tools like mypy check them.
  • Interview phrasing: "Parameter is the variable in the definition; argument is the value passed in the call."
  • Ask: "What does print(greet('Priya')) show?" Two lines: the greeting, then None.

Positional, keyword, default and keyword-only 🚆

Rule 1
Positional arguments come before keyword arguments in a call.
Rule 2
Parameters with defaults come after ones without: def f(a=1, b) is a SyntaxError.
Keyword-only
Everything after a bare * must be named. Full order: (pos, default, *args, kw_only, **kwargs)
Uncomment the last line live to show TypeError: book_ticket() takes from 3 to 4 positional arguments but 5 were given. Explain why keyword-only args make APIs safer: nobody passes "TATKAL" by accident as a berth.

The mutable default trap 🪤 + returning many values

Why it happens: default values are evaluated once, when def runs, not on every call. Every call without cart shares the same list.

A supermarket that gives every new customer the same trolley without emptying it. The second customer finds milk already inside!

Use None as the default and create the list inside. You can even peek at the shared list: add_item.__defaults__.

Interactive · scope · 20–40 min

The LEGB rule: where does Python look for a name? 🔭

Local → Enclosing → Global → Built-in. First match wins.

Click a name to look it up from inside inner().

  • Start with x: found immediately in Local. Then delete local x and look up x again: Enclosing wins.
  • len walks all the way to Built-in. pincode is never defined: NameError.
  • Real-life: looking for your phone charger. Your bag (local), then your room (enclosing), then the house (global), then the shop (built-in).
Scope keywords

global and nonlocal

💥 UnboundLocalError

Remove the global line and visitors += 1 fails. Assigning to a name anywhere in a function makes it local for the whole function, so Python can't read the global one first.

global → module-level variable
nonlocal → variable of the nearest enclosing function (never the global)

Best practice: avoid global. Pass values in and return results out. It keeps functions testable.

Reading a global inside a function is fine without the keyword; only assigning needs it. That distinction is the interview answer.
Live code · functions are objects

First-class functions, lambda, map/filter/reduce 🎓

lambda = a one-line, nameless function
lambda s: s[1]
Only a single expression, no statements.
map transforms every item, filter keeps some, reduce folds them into one value. map/filter return lazy iterators (wrap in list()).

In real code, comprehensions are often clearer: [m + 5 for m in marks]. But sorted(key=lambda ...) is used everywhere.

Ask a student to sort by name instead (key=lambda s: s[0]). "First-class" means a function can be stored in a variable, passed as an argument, and returned: that's what makes closures and decorators (Class 4) possible.
Live code · closures

Closures: functions that remember 🎟️

A closure is an inner function + the variables it remembers from the enclosing scope, even after the outer function has finished.

A coupon printer: set it to 40% once, and every coupon it prints remembers 40%. Each printer (closure) keeps its own setting.

Late binding: closures remember the variable, not its value at that moment. All three lambdas see the final i = 2.

The late-binding loop appears again in the Predict round. Closures are the foundation of decorators next class, so make sure everyone gets make_discount.

Recursion: a function that calls itself 🪆

Russian dolls: open a doll, find a smaller one, keep going until the tiniest doll (base case), then close them back up in reverse order.

No base case → RecursionError: maximum recursion depth exceeded (default limit about 1000 frames).

The 4 pillars of OOP 🏛️

💊

Encapsulation

Bundle data + methods, and control access to the data.

ATM: you press buttons; you can't touch the cash vault.

👨‍👧

Inheritance

A child class reuses and extends a parent class.

Manager IS-A Employee: gets salary, adds a team.

🎭

Polymorphism

Same method name, different behaviour per class.

pay(): UPI, card and cash all "pay" differently.

🎛️

Abstraction

Show what it does, hide how.

Car driver: uses the steering and pedals, not the engine wiring.

Interview tip: for each pillar give definition → real-life example → Python feature: _x/@property, class B(A)/super(), duck typing / overriding, abc.ABC.

Ask 4 students to each pick a pillar and give their own Indian real-life example before revealing the cards (e.g. Aadhaar: you share the number, not the biometric data = encapsulation).
Pillar 1 · live code

Encapsulation: _protected, __private, @property 🔐

_bank (one underscore)
"Internal, please don't touch." Only a convention; Python doesn't stop you.
__pin (two underscores)
Name mangling renames it to _UPIAccount__pin. Avoids clashes in subclasses, but it's not real security.
@property
Getter/setter with normal attribute syntax. The Pythonic way to add validation.
Interview: "Does Python have private variables?" Answer: no true private; _x is a convention, __x triggers name mangling. "We are all consenting adults here."

Polymorphism, duck typing and abstract classes 🦆

🎭 Polymorphism
One call, method.pay(499), many behaviours. The checkout page doesn't care which.

"If it walks like a duck and quacks like a duck, it's a duck." CashOnDelivery isn't a Payment, but it has pay(), so it works.

🎛️ Abstraction
ABC + @abstractmethod = a contract. You can't create a Payment, and every subclass must implement pay().
Ask: "Add a Wallet class (Paytm) without changing the loop." Also mention operator polymorphism: + adds ints, joins strings, merges lists. Python has no method overloading by signature; use default args or *args instead.
Advanced · interview favourite

Multiple inheritance and the MRO 💎

A Smartphone is a Camera and a Phone. Which boot() runs, in what order?

The diamond · MRO order
4Devicebase class
2Camera(Device)
3Phone(Device)
1Smartphone(Camera, Phone)

C3 linearization: child first, parents left → right, a shared base only after all its children. See it with Cls.__mro__.

  • The surprise: inside Camera, super().boot() calls Phone, not Device! super() means "next class in the MRO of the actual object", not "my parent".
  • Device runs only once even though two classes inherit from it. That's what C3 solves.
  • Swap to class Smartphone(Phone, Camera) and run again to see the order change.
Magic methods · live code · a Rupee type

Dunder methods: make your objects feel built-in ✨

print(r) → __str__ lists / REPL → __repr__ a + b → a.__add__(b) a == b → __eq__ a < b, sorted() → __lt__ len(x) → __len__ Rupee(10) → __init__
  • Delete __str__ and rerun: print falls back to __repr__. Delete both: you get <__main__.Rupee object at 0x...>.
  • Interview line: "__str__ is readable for end users; __repr__ is unambiguous for developers, ideally valid code to recreate the object."
  • Without __eq__, == compares identity (like is).
Live code · 3 kinds of methods

Instance method vs @classmethod vs @staticmethod 🎓

Instance method · first arg self
Reads or changes one object's data.
@classmethod · first arg cls
Works with the class: alternative constructors like from_csv or dict.fromkeys.
@staticmethod · no automatic arg
A plain helper function that logically belongs in the class.
Classic interview question. Key phrase: "classmethod receives the class, staticmethod receives nothing, instance method receives the object." Real example: datetime.fromtimestamp() is a classmethod. A classmethod called on a subclass builds the subclass, because cls is the subclass.
🎯 Interview corner · 75–90 min

10 questions you will be asked

What are *args and **kwargs?

*args packs extra positional args into a tuple; **kwargs packs extra keyword args into a dict. At a call, */** unpack.

Why is def f(lst=[]) dangerous?

Defaults are evaluated once at definition, so all calls share one list. Use lst=None and create it inside.

Explain the LEGB rule.

Name lookup order: Local → Enclosing → Global → Built-in. Assigning needs global/nonlocal to target outer scopes.

What is a closure?

An inner function that remembers variables of its enclosing scope after the outer function returns. Used for factories and decorators.

Is Python pass-by-value or pass-by-reference?

Pass-by-object-reference (assignment). A function can mutate a passed list, but rebinding the parameter doesn't affect the caller.

__str__ vs __repr__?

__str__: readable, for users (print). __repr__: unambiguous, for developers. print falls back to __repr__.

@classmethod vs @staticmethod?

classmethod gets cls (alternative constructors, class state). staticmethod gets nothing: a utility function grouped in the class.

Does Python have private variables?

No true private. _x = convention; __x = name mangling to _Class__x. Use @property to control access.

What is MRO?

Method Resolution Order: the order classes are searched for attributes, computed by C3 linearization. See it with Cls.__mro__; super() follows it.

What is self? Is it a keyword?

The instance the method was called on, passed automatically as the first argument. Not a keyword, just a convention.

Pick students at random. Ask for the answer structure: definition → example → one extra detail. Bonus follow-ups: "lambda vs def?" (lambda = single expression, anonymous) and "What is duck typing?"

Watch out

Common mistakes 🚧

Forgetting self

def deposit(amount):

TypeError: BankAccount.deposit() takes 1 positional argument but 2 were given.

print instead of return

total = calc_bill(3)

total is None if the function only prints.

Missing parentheses

print(acc.get_balance)

Prints <bound method ...>. Call it: get_balance().

Mutable default / class list

def f(x, items=[])

Shared between calls or objects. Use None and build it in __init__.

No super().__init__()

class Manager(Employee):

Parent attributes are never set → AttributeError.

Recursion without base case

return n * fact(n - 1)

RecursionError. Always write the stop condition first.
