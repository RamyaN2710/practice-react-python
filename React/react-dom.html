Part 1 · The DOM

What is the DOM?

DOM = Document Object Model. When the browser reads your HTML, it builds a tree of objects in memory. JavaScript can read and change this tree.

  • HTML is the text file you write
  • The DOM is the live tree the browser builds from it
  • Change the DOM and the screen changes immediately
🌳

A family tree

<html> is the grandparent. <body> is the parent. <h1> and <button> are the children.

Every element has a parent, and can have children and siblings, just like a family.

Ask: "Who has seen a family tree?" Draw a quick one on the board if you have one. The word "tree" will come back many times today.

Part 2 · Two packages

React is really two packages

Open package.json in your Vite project and you will find both of them.

🧠

react: the brain

  • Components, JSX, props, state
  • Decides what the UI should look like
  • Works out what changed
  • Does not touch the browser
🤝
🖐️

react-dom: the hands

  • Connects React to the browser DOM
  • Creates, updates and removes real elements
  • Attaches events like onClick
  • Gives us createRoot()

Chef and waiter: the chef (react) decides what goes on the plate. The waiter (react-dom) carries it to your table. In a mobile app, a different waiter (React Native) serves the same chef's food to a phone screen.

  • Version numbers may differ in their project. That's fine.
  • Ask: "Which package would change if we built a mobile app instead?" Answer: only react-dom gets swapped (for React Native). The brain stays the same.

Part 3 · Getting on screen

main.jsx: where React meets the DOM

Line 2: bring in createRoot from react-dom (the hands).
Line 5, part 1: document.getElementById("root") finds the empty box.
Line 5, part 2: createRoot(...) tells React: "you own this box now".
Line 5, part 3: .render(<App />) says "put my App inside it".

StrictMode is a helper for development only. It double-checks your components for mistakes and is not shown on screen.

Part 4 · The 3 steps

Every update has 3 steps

🔔

1. Trigger

Something asks for an update. Usually a state change, like setCount(1).

🍽️ You place an order

🧠

2. Render

React calls your component again, gets new JSX, and compares it with the old one (Virtual DOM).

👨‍🍳 Chef cooks the dish

✅

3. Commit

react-dom changes only the parts that are different in the real DOM.

🛎️ Waiter serves only the new dish

"Render" does not mean "paint the screen". In React, render means "call the component to find out what the UI should look like". The screen only changes in the commit step.

  • Restaurant story: you order (trigger), the chef cooks (render), the waiter brings only the new dish to your table, without clearing your whole table (commit).
  • Make students repeat the three words aloud: Trigger, Render, Commit.

Under the hood

What react-dom translates for you

You write JSX. react-dom turns it into real browser DOM work.

You write (JSX) react-dom does (real DOM)
<h1>Hi</h1> Creates an h1 element and puts "Hi" inside it
className="card" Sets the real class="card" attribute
onClick={handleClick} Listens for clicks (like addEventListener)
style={{ color: "red" }} Sets style.color = "red"
{count} changes 0 → 1 Updates only that text, nothing else
{show && <Popup />} becomes false Removes the popup elements from the page

Golden rule: in React, don't change the page with document.getElementById(...).innerText = .... Change state, and let react-dom update the DOM for you.

Students will learn onClick, state and conditional rendering in Week 2. This table is a preview, so just point out that react-dom does the boring DOM work.
Watch out

Common mistakes 🚧

❌ Wrong id

index.html has id="app" but main.jsx looks for "root".

Result: a blank page and an error saying the target container is not a DOM element.

✅ The two ids must match.

❌ Editing the DOM by hand

Using document.querySelector to change text inside a React component.

React doesn't know about the change and may overwrite it on the next render.

✅ Use state instead.

❌ "Why does it log twice?"

In development, StrictMode runs components twice on purpose to catch bugs.

This is normal. It doesn't happen in the final production build.

✅ Don't panic, it is a helper.

The "logs twice" question comes up a lot once students start using console.log in their Vite apps, so answering it now saves time later.
Check your understanding

⚡ Quick quiz

1. Which package connects React to the browser?

✅ react-dom is the "hands". It creates and updates real browser elements.

2. What does createRoot(document.getElementById("root")) do?

✅ It finds the empty #root box and gives React ownership of it. Then .render(<App />) fills it.

3. In which step does the real screen change?

✅ Commit. Render only works out the plan, and commit applies the changes to the real DOM.

Take a show of hands for each option first. Question 3 is the tricky one, because many students think "render" means drawing the screen.
